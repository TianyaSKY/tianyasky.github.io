## 一、 牛客网实战经验原文归档

- **作者**：青云
- **出处**：牛客网讨论帖 (`https://www.nowcoder.com/discuss/845980287996526592`)
- **核心要点**：
  1. **第一步：AI 诊断**。从 HR（筛人/匹配度）与技术面试官（深度/真实度）双重视角审视空洞描述与薄弱点。
  2. **第二步：STAR 法则重构**。提取 Situation（背景）、Task（任务）、Action（行动）、Result（结果），强调主动语态、难点攻坚与硬核量化数据。
  3. **第三步：按 JD 提取与植入关键词**。提炼必备技能、加分项与缺口，做到“一岗一策，微调细节，大框架不变”。
  4. **第四步：高密度自我评价**。摒弃“吃苦耐劳”等空话，聚焦解决的技术问题与技术理解深度（50 字以内）。
  5. **黄金注意事项**：拒绝 AI 编造虚假数据；必须导出 PDF 并规范命名（`岗位+姓名+联系方式`）；逐字通读检查排版与语病。

## 二、 投递与裁剪标准化操作流程 (SOP)

结合我们的系统工程设计，完整的简历生命周期分为四个阶段：

```
[母简历素材库 master_resume.md] (全量真实资产，绝不造假)
             │
             ▼
[第一阶段：JD 深度解析] ──► 提取必备栈、加分项、高频痛点词
             │
             ▼
[第二阶段：STAR 定向裁剪] ──► 从母简历中提取 3~5 项经历，按 STAR + 主动语态微调
             │
             ▼
[第三阶段：HTML/PDF 渲染] ──► 沿用既有 public/resume 样式，严格单页/双页 A4 导出
             │
             ▼
[第四阶段：标准化投递与复盘] ──► 规范文件命名，面试后将深挖题反哺回母简历题库
```

## 三、 即插即用 Prompt 提示词库

每次投递或更新简历时，可直接复制以下 Prompt：

### Prompt 1：双重视角简历深度诊断
```markdown
角色设定：你是一名资深的技术招聘专家，同时拥有大厂 HRBP 与 后端/AI 架构师（技术面试官）的双重视角。

请深度评估我提供的这段简历内容（或项目描述）：
[粘贴你的简历内容]

求职目标岗位：[如：Python 后端开发工程师 / AI 智能体开发工程师 / 大模型算法工程师]

请分别输出：
1. 【HR 视角筛选分析】：
   - 关键词匹配度（一眼看去是否能在 10 秒内匹配到岗位核心能力）；
   - 是否存在空洞、学生气、或者无意义的套话。
2. 【技术面试官视角深挖分析】：
   - 哪些技术点写得过于泛泛，缺乏实现深度或架构选型思考；
   - 哪些项目缺少具体的业务痛点、技术取舍与量化结果；
   - 预测面试官最可能会就哪几个点进行连环追问。
3. 【改进建议】：列出优先级最高的三处修改点。
```

---

### Prompt 2：STAR 法则硬核重写（控制在 80~120 字）
```markdown
请使用工程级“STAR 法则”重写以下项目经历：

【原始材料】：
[粘贴 master_resume.md 中的对应项目内容]

【优化要求】：
1. 结构紧凑：体现 Situation（背景痛点）+ Task（负责目标）+ Action（具体技术行动）+ Result（量化指标结果）。
2. 主动语态：使用强动作动词（如“主导设计”、“构建”、“推导”、“重构”、“优化”），突出主导作用。
3. 突出工程与算法难点：融入诸如“并发控制”、“内存/资源硬隔离”、“多路召回与融合”、“几何退化解耦”等硬核概念。
4. 真实数据支撑：只使用我原文字里包含的实测数据（如“5小时压缩至1分钟内”、“10-15cm RMSE”、“48.13 MAE”），严禁 AI 凭空捏造数据！
5. 长度限制：分条陈述，单条 60~90 字，语言干练，杜绝形容词堆砌。
```

---

### Prompt 3：按目标岗位 JD 关键词提取与自然融入
```markdown
目标岗位 JD 如下：
[粘贴目标公司的招聘 JD 全文]

我的候选素材库（母简历）：
[粘贴 master_resume.md 中相关技能或项目部分]

请完成以下任务：
1. 【JD 关键词萃取】：
   - 核心硬性技能关键词（Must-have）：
   - 优先加分项关键词（Nice-to-have）：
   - 业务痛点或软性诉求（如高可用、低延迟、跨团队交付等）：
2. 【匹配与缺口诊断】：
   - 我母简历中已具备且能直接呼应的点：
   - JD 中提及但我的简历表述不够突出、需要自然强化的点：
3. 【定制修改方案】：
   - 给出如何将缺失关键词“自然融入”现有项目 Action 中的具体改写建议（拒绝生硬堆砌，必须言之有物）。
```

### Prompt 4：克制型自我评价（50~80 字，非必选）
> *注：若简历项目经历与荣誉已经填满 A4 版面，自我评价可完全省略。若版面有少许空白需垫底，使用此 Prompt。*

```markdown
请根据我的经历总结一段精炼、克制的“自我评价”或“个人画像”。

【我的核心特质】：
- 大连海洋大学综测第一推免至合肥工业大学学硕（211 / 双一流）
- 获蓝桥杯全国第 10 名（国一）、国家级大创第一负责人、中软卓越杯省一等奖
- 主攻 Python/FastAPI 异步架构、Docker 沙箱安全治理、LangGraph/RAG 智能体系统与 3D 视觉几何

【撰写要求】：
1. 严禁出现“学习能力强”、“工作吃苦耐劳”、“具备良好团队合作精神”等一切空话废话；
2. 语言沉稳、客观、专业，突出“数理与算法底子扎实”、“全栈工程闭环能力”与“对底层原理有深究习惯”；
3. 字数严格控制在 50~80 字以内。
```

## 四、 投递实战规范与避坑清单 (Checklist)

### 4.1 命名规范（极为重要，HR 辨识第一关）
- **常规投递命名**：
  `[岗位]_[姓名]_[学校/学历]_[电话].pdf`
  *示例：`后端开发工程师_陈敏祥_合肥工业大学硕士(推免)_135-1700-1469.pdf`*
- **可随时到岗/实习投递命名**：
  `[岗位]_[姓名]_[电话]_[每周X天_持续X月_可随时到岗].pdf`
  *示例：`大模型算法实习生_陈敏祥_135-1700-1469_每周5天_随时到岗.pdf`*

### 4.2 避坑准则
1. **真实性红线**：
   - 面试本质是对简历的“防伪核验”。AI 润色可以优化表达结构，但**绝对不能捏造项目业务体量与技术栈**。母简历中有的才写，没有的绝不硬编。
2. **格式与版面红线**：
   - 投递一律使用 **PDF** 格式，严禁投递 `.doc` 或 `.html`；
   - 严格控制在 **1 页整** 或 **2 页整**，严禁出现第 2 页/第 3 页仅有 2~3 行的“溢出悬挂行”（孤行）；
   - 打印样式确认：在浏览器中使用 `Ctrl/Cmd + P`，选择 A4、100% 缩放、无边距，背景图形勾选，确认字体渲染无折行。
3. **闭环反哺机制**：
   - 每次面试结束后，不管通过与否，复盘面试官提问最刁钻的 2~3 个问题，立刻记入 [docs/master_resume.md](file:///home/tianya/Documents/tianyasky.github.io/docs/master_resume.md) 的“面试追问与防守”栏目中，让母简历成为越战越强的个人资产。
