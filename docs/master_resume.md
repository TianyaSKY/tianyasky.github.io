### 3.1 SKYCloud (SKYNetdisk) —— AI 原生云存储与智能体协作工作区

- **一句话定位**：将云存储底座、RAG 多路检索与 Docker 受控沙箱融合的 AI Workspace 与智能体运行时平台。
- **角色与规模**：项目负责人 & 独立主导核心全栈架构设计（个人独立研发）。
- **技术栈**：Vue 3、FastAPI、PostgreSQL、pgvector、Redis、RabbitMQ、Docker、FastMCP、OpenCode Runtime、LangGraph。
- **技术要点（做了什么 + 为什么这么做）**：
  1. **存储底座与秒传设计**：基于 SHA-256 哈希实现物理内容寻址与逻辑目录解耦，实现同哈希文件极速秒传与去重；支持大文件分片上传、断点续传、在线 Markdown/图片预览、格式转换与带有效期的公开分享链接。
  2. **多路融合 RAG 检索管线**：离线经 RabbitMQ 异步对文件进行分块（Chunking）与 1024 维向量生成；在线检索引入 6 维关键词改写与 Multi-Query 生成，并行完成语义向量召回与关键词检索，使用倒数排名融合（RRF）算法与 Cross-Encoder Rerank 重排，支持页面级与图片引用溯源。
  3. **双模式助手与沙箱隔离**：划分为“快速模式”与“专家模式”。快速模式保持只读并提供流式 RAG 问答；专家模式为每个用户工作区动态拉起独立 Docker 容器沙箱与 OpenCode Runtime，驱动 Coding Agent 在安全边界内编辑文件、执行 Bash 命令并返回 Diff。
  4. **HITL 人机协同与 FastMCP 协议规范**：引入 LangGraph 构建 ReAct 决策流，针对高危文件修改设计 Human-in-the-Loop (HITL) 人工确认拦截机制；基于 FastMCP 协议规范暴露 16 个 Tool、4 个 Prompt、2 个 Resource，对外签发带时效的刷新 Token，支持 Claude Desktop 与 Cursor 等外部生态调用。
- **难点与技术取舍**：
  - **难点**：大模型执行代码与文件整理具有不确定性，在云盘环境中若直接赋予文件系统写权限，极易造成数据破坏或提权逃逸。
  - **方案与取舍**：坚持区分“读取知识”与“执行动作”。没有采用轻量的单进程直接调用，而是为专家模式建立独立的 Docker 沙箱容器生命周期管理；所有的系统写操作必须生成 Diff 补丁并交由前端弹窗给用户人工确认（HITL），宁可牺牲全自动化的纯连贯性，也要确保数据的不可破坏性。
- **实测数据**：
  - 暴露 `16 Tools / 4 Prompts / 2 Resources` 标准 MCP 接口；
  - 向量检索维度：`1024 维` 高维语义嵌入；
  - 斩获：第七届中软国际 · 卓越杯 AI 挑战赛辽宁赛区**一等奖**。

> **面试追问与防守（SKYCloud）**：
>
> - **追问 1**：“向量数据库你为什么选择 PostgreSQL + pgvector，而不是专用的 Milvus 或 Pinecone？”
>   - **回答思路**：“核心考量是系统事务一致性与运维成本。在网盘系统中，文件的元数据（权限、父子目录树、分享过期时间、软删除状态）与向量分块强绑定。使用 pgvector 可以在同一个事务内保证‘文件删除时向量级联删除’，杜绝分布式环境下数据库与外部向量引擎状态不同步产生的幽灵数据；其次，单节点 pgvector 配合 HNSW 索引在千万级以下分块检索中延迟完全在 20ms 以内，满足工作区业务需求。”
> - **追问 2**：“RRF (Reciprocal Rank Fusion) 的公式是什么？为什么不直接把向量得分和 BM25 得分加权相加？”
>   - **回答思路**：“RRF 公式为 $RRF(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}$（通常 $k=60$）。直接将向量 Cosine 分数与 BM25 分数加权相加存在严重的量纲失配问题，BM25 理论上无上界且受长短句影响极大，Cos 分数则在 [-1, 1] 之间，需要复杂的动态归一化且极难调参。而 RRF 抛弃绝对分值，仅采用候选在各自排序列表中的名次进行无量纲融合，鲁棒性极强。”

### 3.2 SKYDouyin —— 短视频推荐系统与高并发闭环 MVP

- **一句话定位**：覆盖上传、事件总线解耦、双路召回与冷启动画像的端到端短视频推荐闭环系统。
- **角色与规模**：项目负责人（个人独立完成后端架构、推荐服务与双端对接）。
- **技术栈**：Spring Boot 3、FastAPI、PyTorch、Milvus、Redis、MySQL、RabbitMQ、React 18、Android、Docker Compose。
- **技术要点（做了什么 + 为什么这么做）**：
  1. **微服务与业务边界解耦**：Spring Boot 负责维护业务真实数据（用户、关注关系、视频元数据与权限），FastAPI 专注承担高负载的特征向量提取与推荐算法服务；两者通过 RabbitMQ 异步解耦，保证业务端轻量与计算端独立扩展。
  2. **视频上传发布流水线**：前端/客户端预计算文件哈希，经初始化、分片上传、合并与元数据落库；完成后向 RabbitMQ 发布 `event.video_embedding` 事件，由消费者异步调用深度学习模型生成 1024 维内容表征并入库 Milvus，发布接口响应时间降至毫秒级。
  3. **双路召回与融合排序**：React Web 与 Android 客户端埋点统一上报播放时长、完播率、点赞与停留等事件。推荐引擎采用“热门高质量候选池 + 基于用户近期行为向量的 Milvus 近邻召回”双路策略，两路候选在 Redis 判重过滤后进行长短期偏好打分排序。
  4. **新用户冷启动画像建模**：针对无交互历史的新用户，设计基于内容标签聚合的冷启动方案：后台定时将已发布视频的标签向量在 Redis 中预聚合并缓存，新用户注册勾选兴趣标签后，即时对其所选标签向量求加权均值作为冷启动初始画像，消除空白推荐。
  5. **互动高并发与幂等防重**：点赞与收藏使用 MySQL `(user_id, video_id)` 联合唯一键建立真相表，防止重复入库；互动计数不在每次点击时直接写 MySQL，而是先在 Redis 中进行原子累加（INCR），由定时异步任务批量回写落库，化解高频交互对数据库的 IO 压力。
- **难点与技术取舍**：
  - **难点**：多模态向量生成极其耗时（秒级），若在上传发布时同步等待，会导致客户端大量超时并霸占服务器连接。
  - **方案与取舍**：引入 RabbitMQ 异步事件解耦，上传只需确认文件元数据即宣告成功，向量生成与召回候选入库由后台独立消费；同时在消费端引入重试与幂等消费机制，保证即使模型服务抖动，事件也不会丢失。
- **实测数据**：
  - 支持 Web 与 Android 双端无缝交互；
  - Milvus 1024 维向量召回检索延迟：`<15 ms`；
  - 具备完整的秒传、断点续传、标签冷启动与点赞高并发防刷能力。
- **代码链接**：
  - 代码仓库：[github.com/TianyaSKY/SKYDouyin](https://github.com/TianyaSKY/SKYDouyin)

> **面试追问与防守（SKYDouyin）**：
>
> - **追问 1**：“点赞数在 Redis 中缓存，定时批量回写 MySQL，如果 Redis 意外宕机如何保证数据一致性？”
>   - **回答思路**：“首先，我们在 Redis 开启了 AOF 每秒刷盘（appendfsync everysec）；更关键的是，在业务设计上，用户的‘点赞行为明细记录’是直接走 MySQL 事务入库的（有唯一索引防重），Redis 只负责承担汇总计数的读写缓冲。如果 Redis 发生非可控宕机，后台校准 Worker 会扫描指定时间段内的点赞明细表 `COUNT(*)`，重新校准并对齐点赞总数。”

### 3.3 SKYOJ —— 面向高校教学的 AI 在线评测平台与安全隔离沙箱

- **一句话定位**：支持 ACM / OOP / Kaggle 多模式评测与 Docker 资源硬隔离的高校教学评测系统。
- **角色与规模**：独立设计与开发（个人开源项目）。
- **技术栈**：Vue 3、FastAPI、SQLAlchemy、MySQL、RabbitMQ、Celery、Docker、Linux Cgroups、Monaco Editor。
- **技术要点（做了什么 + 为什么这么做）**：
  1. **多模式评测协议统一化**：突破传统 OJ 仅支持 ACM 标准 I/O 对拍的局限，统一支持面向对象（OOP）单元测试用例黑盒验证、以及按 RMSE/Accuracy 等自定义评分脚本评分的数据科学（Kaggle 模式）任务。
  2. **异步队列与 solo 调度**：API 采用 Outbox 模式落库，经 RabbitMQ 投递；拆分为 `judge`（代码判题）、`ai`（智能助教）、`file`（文件处理）三个独立 Celery 队列。判题 Worker 强制以 solo 单进程模式运行，确保每个提交任务独占 CPU 算力，杜绝并发竞争导致运行耗时误判。
  3. **基于 Docker + Cgroups 的安全硬隔离**：判题容器强制启用 `network=none` 物理断网，基于 Linux Cgroups 严格限制 CPU 配额、内存上限（触发 OOM 立即终止）以及最大进程数（`pids-limit` 防止 Fork 炸弹）；仅 judge Worker 单独挂载只读 Docker Socket，严格缩小提权风险。
  4. **启发式 AI 助教集成**：接入 LLM 接口，设计苏格拉底式启发性提示词，根据学生代码语法错误或运行测试失败信息给出排错线索与边界测试思路，严格限制直接向学生输出完整解题源代码。
- **难点与技术取舍**：
  - **难点**：学生提交的代码不可控，存在恶意利用 `while(1) fork()` 耗尽系统 PID、恶意读写 `/etc/passwd`、或对外发起内网扫描等安全风险。
  - **方案与取舍**：坚决摒弃开销较小的直接沙箱（如直接用 `subprocess`），全部通过动态生成的轻量 Docker 隔离执行；以断网、非特权、Cgroups 硬上限以及超时租约（Lease Timeout）由 `job-recovery` 守护进程强制销毁，彻底从操作系统层面切断攻击面。
- **实测数据**：
  - 覆盖 ACM / OOP / Kaggle 3 大评测范式；
  - 判题并发调度延迟：`<100 ms`；
  - 100% 拦截 Fork 炸弹、内存溢出与恶意网络嗅探。
- **代码与演示链接**：
  - 代码仓库：[github.com/TianyaSKY/SKYOJ](https://github.com/TianyaSKY/SKYOJ)
  - 介绍视频：`https://media.tianyasky.top/skyoj-intro.mp4`

> **面试追问与防守（SKYOJ）**：
>
> - **追问**：“判题 Worker 使用 Celery solo 模式单进程串行，在高并发考试场景下如何应对吞吐瓶颈？”
>   - **回答思路**：“单个 Worker 采用 solo 模式是为了防止单机多线程争抢 CPU 资源导致‘执行时间测量不准’。当面对大规模考试提交高并发时，我们通过横向扩展（Scale-Out）启动多个独立的 Worker 容器实例，每个实例各自消费队列中的一个 Task。这样既保证了每个判题任务在各自物理核上的时间度量准确性，又能通过分布式水平扩容线性提升系统吞吐。”

### 3.4 单目视觉三维坐标重建系统 (科研 / 论文 / 国家级大创第一负责人)

- **一句话定位**：融合五级级联深度学习与反投影射线夹角几何守恒的无 GPS 近海结构化杆体单目高精度定位系统。
- **角色与规模**：第一负责人 & 论文第一作者（国家级大学生创新训练项目，指导教师：李明智）。
- **技术栈**：Python、PyTorch、YOLO11、OpenCV、SimpleCNN、Non-Linear Least Squares (LM/TRF)、Jetson Orin。
- **业务背景与痛点**：
  - 在近海养殖、渔船系泊、港口堆场等复杂环境中，GPS/北斗信号易受遮挡甚至丢失；传统人工标记（AprilTag/ArUco）极易受海水腐蚀污损；
  - 采用经典透视 n 点算法（PnP）时，一旦特征点分布在共线或共面细长杆状结构上，会发生严重的**几何退化（Collinear Degeneracy）**，导致旋转与平移矩阵奇异，定位误差从厘米级跳变到数米。
- **技术要点（做了什么 + 为什么这么做）**：
  1. **五级级联鲁棒感知流水线**：
     - `第1级`：轻量级 YOLO（POLES.pt）粗定位杆状物并生成二值 ROI 掩膜，将特征点搜索空间大幅压缩 `95% 以上`；
     - `第2级`：在掩膜约束的感兴趣区域内执行 Harris 算法捕获几何角点；
     - `第3级`：设计定制三层卷积网络（SimpleCNN）对 64×64 局部图像块执行 9 分类推理（8 个空间物理特征点 + 1 个背景噪声），在 1377 张样本上实现 `100%` 语义分类与杂波过滤，彻底消除无纹理场景下的 2D-3D 关联歧义；
     - `第4级与第5级`：执行分类别非极大值抑制（Class-wise NMS）与 `cornerSubPix` 亚像素迭代精炼，获取高精度物理角点亚像素坐标。
  2. **反投影射线夹角几何守恒解耦**：
     - 推导基于光学射线夹角守恒的非线性最小二乘位姿优化模型。通过相机内参将 2D 像点反投影为归一化方向向量，构建其两两夹角与三维世界点方向夹角的一致性残差。
     - 该方法将原本对旋转平移耦合敏感的 6-DoF PnP 求解，降维转化为**仅依赖相机三维空间坐标 $(X, Y, Z)$ 的 3-DoF 良态非线性优化**，从数学原理上规避了共线退化。
  3. **多初值并发与 LM/TRF 双优化引擎**：
     - 设计融合时序滤波平滑、PnP 粗估计及 3D 点几何中心的多候选初值策略，并发调用 Levenberg-Marquardt (LM) 与 Trust Region Reflective (TRF) 双优化引擎，根据最终反投影残差自动选取全局最优解。
- **实测数据与消融实验**：
  - **理论精度**：仿真基准下解算成功率 `100%`，平均理论重构精度达到 `1.1×10⁻⁵ m`；
  - **海试实测**：在大连沿海实测海试中，定位 RMSE 精度达到 `10–15 cm`；
  - **消融验证**：消融实验证实，若移除 CNN 语义分类模块，几何启发式匹配错位导致误差恶化至 `5.38 m`；若移除 NMS 后处理，冗余点干扰导致误差恶化至 `6.13 m`；
  - **边缘部署**：在嵌入式边缘计算终端 Jetson Orin 上实现 `26 FPS` 实时流畅运行。
- **荣誉与成果**：
  - 获国家级大学生创新训练项目立项与结项推荐；
  - 论文成果获辽宁省大学生创新创业年会**三等奖**，已获批相关软件著作权。

> **面试追问与防守（单目定位系统）**：
>
> - **追问**：“为什么射线夹角守恒能够消除相机旋转矩阵 $R$ 的影响，将 6-DoF 降维到 3-DoF？”
>   - **回答思路**：“因为向量点积具有旋转不变性。在世界坐标系下，空间中任意两点 $P_i, P_j$ 与相机光心 $C$ 的连线夹角余弦值为 $\frac{(P_i - C) \cdot (P_j - C)}{\|P_i - C\| \|P_j - C\|}$，这个值只由相机位置 $C$ 和三维点世界坐标决定。而在相机坐标系中，反投影射线 $f_i = K^{-1} u_i$ 经过单位归一化后，两条射线的夹角余弦即为 $f_i \cdot f_j$。由于旋转矩阵 $R$ 是正交矩阵，旋转不改变向量夹角，因此理论上这两者必然相等。这样就在残差方程中彻底去除了未知旋转矩阵 $R$，只剩下相机位置未知数 $C=(X, Y, Z)$，使方程状态数减半，彻底消除了共线退化导致的病态奇异。”

### 3.5 YOLO-PGMD 人群计数系统 (科研 / 论文)

- **一句话定位**：基于概率引导注意力与局部重归一化积分守恒的高分辨率密集人群密度估计网络。
- **角色与规模**：独立研发 / 论文第一作者。
- **技术栈**：Python、PyTorch、Ultralytics YOLO、PG-Attention、ECA Net、Smooth L1、MSR 膨胀卷积。
- **业务背景与痛点**：
  - 密集人群存在极大的尺度跨度、严重肢体遮挡与透视畸变；传统回归网络在稀疏背景处虚警严重，在密集处漏检；
  - 传统基于高斯核生成的密度图标签，在图像边缘裁剪时会导致高斯核能量被截断截断，导致全图密度积分小于实际人头数（$\sum D < N$ 产生系统性偏小偏差）。
- **技术要点（做了什么 + 为什么这么做）**：
  1. **局部重归一化积分守恒高斯标签**：提出严格保证能量守恒的密度标签生成算法，对受图像边界裁剪的高斯核进行局部重新归一化，使得连续积分值与真实标注点数严格恒等（$\sum D \equiv N$），根除训练源头的系统性负偏差。
  2. **概率引导空间注意力机制（PG-Attention）**：提取 YOLO P2/P3/P4 多尺度特征，设计概率预测分支（Probability Head）预估人头前景存在似然度（受 BCE + 0.2 Dice 约束）；将前景概率作为空间先验与 ECA 通道注意力结合，配合三级膨胀残差卷积（MSR，膨胀率 1, 2, 3）扩展感受野，全程维持 Stride-4 (160×160) 高分辨率表征。
  3. **分层复合损失函数设计**：设计包含前景概率似然损失、1.5 阶幂律样本归一化密度损失、全图相对人数损失及 4×4 局部网格空间分布约束的四任务联合损失，有效兼顾稀疏与极端超密集区域。
- **实测数据（4 大国际公开基准评测）**：
  - **ShanghaiTech Part A**（超密集）：取得 `48.13 MAE / 74.17 RMSE`（大幅超越经典顶会基准 CSRNet 与 Bayesian Loss）；
  - **JHU-Crowd**（复杂恶劣环境）：取得 `39.73 MAE`；
  - **ShanghaiTech Part B**（稀疏）：取得 `13.20 MAE`，相对误差 NAE 仅 `0.091`；
  - **UCF-QNRF**：取得 `90.79 MAE / 137.50 RMSE`。
- **成果**：独立完成论文稿《YOLO-PGMD: 概率引导多尺度特征融合与积分守恒人群密度估计网络》。

> **面试追问与防守（人群计数系统）**：
>
> - **追问**：“为什么要在密度估计前引入一个概率分支（Probability Head）？这和直接让网络回归密度图有什么区别？”
>   - **回答思路**：“传统密度图回归网络最大的弊病是在空旷背景（如树木、建筑纹理、地面杂波）容易出现微弱的非零假阳性响应，这些微小噪声在整张大图上累加起来会形成不可忽视的虚假人数。引入概率分支通过严格的二值交叉熵和 Dice 损失强制学习‘这里到底有没有人头’的前景掩码，以此作为强先验去门控抑制背景特征，将背景假阳性几乎降为零，极大增强了模型在稀疏与背景复杂场景下的抗虚警能力。”

### 3.6 科幻奇点 (Cixin Singularity) —— 大语言模型微调

- **一句话定位**：单卡 RTX 5090 采用 4bit NF4 QLoRA 微调 Qwen3.6-27B 达成刘慈欣硬科幻文风续写对齐。
- **角色与规模**：项目负责人（个人独立完成数据集清洗、对齐与微调）。
- **技术栈**：Python、PyTorch、Qwen3.6-27B、4bit NF4、LoRA、trl、bitsandbytes、RTX 5090。
- **技术要点（做了什么 + 为什么这么做）**：
  1. **低资源高参数微调方案**：在消费级单卡 RTX 5090 (32GB) 上以 4bit NF4 量化和 BF16 精度加载 Qwen3.6-27B，在全量注意力投影层（q/k/v/o_proj）注入 rank=16、alpha=32 的 LoRA 适配层，可训练参数仅占 `0.039%` (10.5M)，适配器文件大小仅 `20 MB`。
  2. **时序无泄露切分与 Completion-only 掩码**：构建 2375 条高质量续写样本，按小说时序章节连续切分（train 1900 / val 238 / test 237，杜绝跨切分数据交叉污染）；基于 trl 采用 `completion_mask` 将 prompt 及指令 tokens 的 label 统一置为 -100，确保模型仅对模型输出的续写内容计算梯度，杜绝死记提示词。
  3. **严格训练收敛与平截断选型**：设置 paged_adamw_8bit 优化器、有效 batch size=16、2048 上下文长度与梯度检查点；在 1.0、1.5、2.0 epoch 保存快照，在第 1.5 epoch 观察到验证集损失走平（3.124 → 3.122），结合人工双盲文风评测锁定最佳 checkpoint。
- **实测数据**：
  - 训练耗时：`3.1 小时`（238 步完成 2 epoch）；

  - 损失指标：Train loss 从 4.59 降至 2.97，Eval loss 收敛至 3.122，Token 预测准确率由 0.22 提升至 0.43。
